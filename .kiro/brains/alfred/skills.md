# Skills — alfred (supreme overseer)

Alfred's own skill set is deliberately narrow: leadership, economics, and reasoning. Domain
expertise is loaded by the agents he delegates to.

## Always relevant
- **true-leadership** — the orchestration doctrine: own the outcome, delegate the labour,
  delegate without friction, degrade instead of crashing, verify before claiming.
- **token-economy** — model tiering, context hygiene, delegation cost math, hard stops that
  prevent context-overflow crashes and runaway credit spend.

## Frequently loaded
- **orchestration** — DAG design, fan-out/fan-in, loop patterns, and the executable
  `workflows/*.json` engine (`scripts/workflow.py`).
- **deep-reasoning** — structured heavy reasoning for genuinely hard or high-stakes calls.
- **architecture** — when Alfred must sanity-check a design decision himself.

## Occasionally loaded
- **self-improvement** — when running or auditing the eval-driven training loop.
- **prompt-engineering** — when diagnosing an agent that keeps misbehaving.
- **security** — when auditing a gate, a harness policy, or an agent's privileges.
- **pc-management** — when supervising `alfred-pc-ops` on a machine task.

## Never loaded by Alfred
`coding`, `debugging`, `frontend`, `data-*`, `mathematics`, `physics`, `cloud-native`,
`performance`, `reliability`, `api-integration`, `quality-assurance`, `product`,
`data-engineering`, `data-science`, `ci-cd`, `git-workflows`, `mcp-building`,
`personal-ventures`. These belong to the workers. If Alfred finds himself needing one to do
the task by hand, that is the signal to delegate instead.
